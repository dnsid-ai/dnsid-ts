# @dnsid-ai/foundry

Known Foundry named Live creation for the Identity Digital registry. This Node.js package is separate from the protocol core; `@dnsid-ai/sdk` does not import or re-export it.

## Contract and server gate

Implements the [Known Foundry create contract at compliance commit `e01bcf3`](https://github.com/dnsid-ai/dnsid-sdk-compliance/blob/e01bcf3/docs/sdk-design/13-known-foundry.md).

The package is marked `private: true`, so the release workflow skips packing and publishing it. Remove that flag only after the [initial-create server acceptance checks](https://github.com/dnsid-ai/dnsid-sdk-compliance/blob/e01bcf3/docs/known-foundry-server-requirements.md#acceptance-checks) pass, and record the accepted server revision with the SDK release. Acceptance includes returning the terminal identity for its key and refusing terminal-name replacement for new or unrelated keys; without local state, the SDK cannot detect a replacement. There is no sandbox fallback, ordinary-registration fallback, or capability probe beyond authenticated onboarding.

While the package is private, it is excluded from the public API reference and index. Add it back to `scripts/build-docs-reference.mjs` (`PAGES`) and `typedoc.json` when it is published.

`create(name, options?)` loads environment configuration when `options.config` is absent. Explicit merged configuration does not re-read the environment. `FoundryConfig` is a plain data type owned and exported by the config loader (`@dnsid-ai/sdk/node`), not by Foundry. Registry credentials are separate from configuration. Applications can inject the registry, key provider, public DNS/HTTPS dependencies, log registry, and store through the same options.

Names are exact Unicode strings, not domains: no trimming, case changes, or Unicode normalization. The server allocates the domain. Create persists registration facts but does not wait for public ACTIVE. A challenge-free replay without a domain saves the ID and status and returns a resumable error. Until both ID and domain are saved, the next `create()` replays the same frozen request and registration key. It does not search the agent list.

`active({signal?, timeoutMs?})` finishes proof and shared managed issuance, then verifies fresh public DNS, HTTPS, current keys, status, and lifecycle-log evidence. Initial setup does not scan lifecycle history before preparation unless the registry is already READY with no saved ISSUANCE; then it recovers the existing ISSUANCE and never prepares another. Saved accepted issuance is verified without resubmission. An issuance rejection (`IDEMPOTENCY_MISMATCH`, `TLOG_PREPARATION_MISMATCH`, or `TLOG_INVALID_ENTRY`) triggers lifecycle recovery; empty history or a missing ISSUANCE returns a resumable error rather than authorizing new preparation. `TLOG_INVALID_ENTRY` remains resumable and preserves the registry code pending E2 #46. After an unsettled proof expires while the registry still waits for it, `active()` requests a reissue. A successful reissue replaces the saved challenge and signature. HTTP 409 records that the challenge was used and waits for registry status without resubmitting it. Registry READY does not imply protocol ACTIVE. Default deadlines are 30 seconds for `create()` and 10 minutes for `active()`; callers can override either with `timeoutMs`. Polling and transient retries start at 1 second, double to a 15-second cap, and stay within the call's deadline. Cancellation retains progress and never cancels the server identity. Non-cancellable provider calls are checked before and after; the provider must bound its own calls.

`sign(bytes)` adds no signature format. It shares its pause controller with profile helpers built from `identityManager()`. Until registry publication configuration is durably saved, `identityManager()` throws `SigningPaused` and creates nothing. Later calls return one normally constructed manager. Signing remains paused until public readiness succeeds. Reopening a completed operation with saved state checks the saved current public-key binding without DNS/log calls; `active()` refreshes it. Saved terminal status or a signing pause prevents signing after restart. Terminal or key-binding failures persist before signing is paused; only a successful `active()` clears a mismatch pause, and terminal state is never cleared. A deadline or cancellation during refresh leaves an already enabled signer enabled. Direct access to the underlying provider is outside this guard. After rotation, a replica without saved state derives its registration key from the frozen creation key (its current provider key). It recovers the earlier ISSUANCE through verified rotation history, saving the ISSUANCE key as the initial key and the creation key as the current key. Signing still requires verified public `ku` to match. Replay domain support and current-key replay remain subject to the server gates.

## Storage and recovery

`FileFoundryStore` defaults to `~/.dnsid/foundry/`. State paths digest the registry URL, organization ID, and exact name. `proof-pending` lasts until its outcome is saved; then `identity-known` covers ISSUANCE preparation and submission until acceptance. Files are owner-only, atomically renamed, and fsynced. Each call holds an in-process/cross-process lock, reloads state, and releases the lock only after writes finish. Locks do not expire while their owning process lives; an observed dead process can be reclaimed. PID reuse conservatively leaves the operation busy until that process exits. The lock is safe on one host and in one PID namespace only. Do not share the directory across hosts or containers: reclaim checks the local PID and can remove a lock held elsewhere. Use a local filesystem with atomic directory rename and file/directory fsync. Inject a store with equivalent locking and durability for shared storage.

Export and import use version-1 UTF-8 JCS recovery documents. Duplicate members, invalid Unicode, unsupported phases/versions, conflicting input, and invalid completed-byte hashes are rejected. Unknown members survive rewrites. Recovery files contain public bindings and provider references, never private keys or registry credentials. Save a backup of recovery files **and** independently recoverable provider keys. Back up the whole directory, including historical identity snapshots. Container-local storage is lost when its volume is removed. An ephemeral injected checkpoint store does not supply restart-persistent log rollback protection; inject a log registry with a durable checkpoint store when required.

Create never generates, provisions, or selects a key. An empty provider (`listKeyIds()` returns an empty list) returns `KEY_MISSING`; create the key first, for example through explicit KMS-first creation. Key provisioning and replica convergence remain the provider's responsibility. A missing or different key never triggers replacement.

`foundry.organizationId` and `foundry.governanceId` come only from the deployment file or code. `DNSID_GOVERNANCE_ID` configures ordinary `dnsid.identity.governanceId`, not Foundry's expected GI.

CLI, hosted cross-SDK scenarios, key-provider provisioning internals, rotation, and retirement/revocation workflows are not implemented here. Same-name replacement is disabled and returns a terminal error.
